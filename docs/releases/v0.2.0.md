The second preview of ssbm-rs: Super Smash Bros. Melee running natively, from your own copy of the game. This one fixes frames that dropped out, camera snapshots, a timing difference from the console and a CPU AI decision, and can record your sessions for bug reports.

## What's new

- **No more dropped frames.** About once a match, a frame lost the stage, the fighters or the background and showed only the background color and the HUD. This happened when part of the scene sat just behind the camera. Those frames now draw whole, as close to Dolphin's software renderer as any other frame.
- **Camera snapshots save properly.** Snapshots taken in Camera Mode used to reach the memory card as noise. They now show the scene in the Data menu's snapshot album.
- **Closer to the console's timing.** A cancelled timer or stopped audio transfer used to wake the game one extra time, which no console does. It could shift timing, such as audio after a disc read during Pokémon Stadium's transformations.
- **CPU opponents.** When a CPU's target was in the air past both ends of the stage, the AI picked where to go from a leftover value on the stack that held something different from the console's, so the CPU could head somewhere else. It now heads where it would on a console.
- **Ice Climbers.** Nana's DI now uses her actual stick position. It could pick up a stale value.
- **Session recordings.** Create a folder named `recordings` in the settings folder (`%APPDATA%\ssbm-rs` on Windows, `~/.config/ssbm-rs` elsewhere), and each session's controller inputs are saved there with a copy of the memory card as it started. A recording replays the session exactly, so attaching one to a bug report lets the bug be reproduced.
- **Crashes keep your progress.** If the game crashes, it now saves the memory card's pending changes, and the recording, before showing the message. Closing that window no longer loses them.
- **A lost GPU says so.** If the graphics driver resets or the GPU is lost mid-session, the error now names the GPU and the reason instead of a confusing message about a buffer.

The game logic uses a little more CPU than in 0.1.0, about 4 to 7%, and copying the screen into memory adds about 9% on stages that do it every frame. This only matters on a machine that barely kept up with 0.1.0.

## Get started

1. Download the file for your system:
   - **Windows 10 or 11 (64-bit):** `ssbm-rs.exe`
   - **macOS 11 or later (Apple silicon or Intel):** `ssbm-rs-macos.zip`. Unzip it and move `ssbm-rs.app` to Applications.
   - **Linux (x86-64):** `ssbm-rs-x86_64.AppImage`. Mark it executable (in its file properties, or `chmod +x`).
2. Open it. The first time, it asks for your disc image of Melee, NTSC version 1.02 (game ID GALE01, revision 2), as an `.iso`, `.rvz`, `.ciso` or `.gcz` file. It remembers it, so later launches go straight to the game.

If you used 0.1.0, replace it with the new file. Your memory card and the remembered disc stay where they were.

The release contains no game data. Other versions of Melee and modded discs aren't supported.

## The first launch on each system

These builds aren't signed by a paid certificate, so each system asks once whether to trust them:

- **Windows:** if SmartScreen says "Windows protected your PC", choose **More info**, then **Run anyway**.
- **macOS:** if it says Apple can't verify the app, open **System Settings → Privacy & Security** and choose **Open Anyway** next to ssbm-rs.
- **Linux:** the disc picker uses your desktop's file chooser (any major desktop has one); message boxes use `zenity` when it's installed.

## Playing

Keyboard, gamepads and GameCube controllers through a Wii U-style adapter all work; the [README](https://github.com/itsarahtonin/ssbm-rs/blob/v0.2.0/README.md#controls) has the controls. On Windows, the adapter needs the WinUSB driver (installed with Zadig, as for Dolphin). Your memory card and the remembered disc live in an `ssbm-rs` settings folder (`%APPDATA%\ssbm-rs` on Windows, `~/.config/ssbm-rs` elsewhere).

## What to expect

This is a development preview. The game's code is translated into Rust and checked against the original, but that verification is still in progress, and the renderer approximates some of the GameCube's graphics hardware. The Windows build has been played the most. If something looks, sounds or plays wrong, please report it with your system and what you were doing, and a session recording if you have one. See [verification and limitations](https://github.com/itsarahtonin/ssbm-rs/blob/v0.2.0/docs/verification.md) for details.
